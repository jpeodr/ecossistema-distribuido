Arquitetura de solução

Um sistema distribuído que lê dados públicos do IBGE (SIDRA): o trabalho é dividido entre várias máquinas, que executam ao mesmo tempo.

O básico #

Cada pedido vira 27 tarefas, uma por Unidade da Federação. Três processos participam:

Organiza

Manager

Cria as tarefas, recebe os resultados e monta o relatório.

Guarda a fila

Redis

Fila compartilhada: o Manager coloca tarefas, os Workers retiram.

Executa

Workers

Consultam o SIDRA e devolvem os dados ao Manager.

Um Worker não conhece os outros e não sabe quantos são. Para ter mais capacidade, basta subir mais Workers:

docker compose up -d --scale worker=5

A animação é ilustrativa; contadores, tempos e log vêm do sistema real.

  1. Pedido — o navegador pede um job para a pesquisa escolhida.
  2. Divisão — o Manager cria 27 tarefas, uma por UF.
  3. Fila — as tarefas entram no Redis.
  4. Consumo — cada Worker retira uma tarefa da fila.
  5. Coleta — o Worker consulta o SIDRA e organiza os dados.
  6. Devolução — o Worker manda o resultado ao Manager.
  7. Relatório — quando todas chegam, o Manager soma e monta as tabelas.
  8. Leitura — o painel mostra o relatório.

Paralelismo #

Paralelismo é fazer várias partes do trabalho ao mesmo tempo. Ele aparece em três lugares:

  • Entre as máquinas — as 27 tarefas são divididas entre os Workers.
  • Dentro de cada Worker — até 4 consultas ao SIDRA ao mesmo tempo.
  • Dentro de cada tarefa — a organização dos dados roda em outra thread.

Com 3 Workers e 4 consultas cada, o sistema faz 12 consultas ao SIDRA ao mesmo tempo.

As duas fórmulas da aula #

Como aprendemos em aula com o professor Vitório, o Speedup mostra quanto o sistema ganhou e o Speedup Máximo mostra o quanto ele pode ganhar.

Fórmula 1

Speedup

S = T₁ / Tₚ
  • T₁ — tempo em série, uma tarefa por vez.
  • Tₚ — tempo em paralelo.
  • S — quantas vezes ficou mais rápido.
Fórmula 2

Speedup Máximo

S_max = 1 / ((1 − P) + P / N)
  • P — parte do trabalho que dá para paralelizar.
  • 1 − P — parte que só uma máquina pode fazer.
  • N — quantas tarefas rodam ao mesmo tempo.

Exemplo da aula, com 80% do trabalho paralelizável: 4 máquinas dão no máximo 2,5×, 16 dão 4×, e nem infinitas máquinas passam de 5×.
