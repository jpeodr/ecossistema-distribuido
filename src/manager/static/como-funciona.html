A animação é ilustrativa (movimento desacelerado para leitura); números, tempos e log vêm do sistema real: cada linha é uma tarefa real concluída por um Worker. Legenda: amarelo = tarefa publicada · azul = tarefa retirada da fila · verde = consulta ao SIDRA · roxo = callback ao Manager.

3 · O caminho de um clique

1

Pedido

O navegador envia POST /api/v1/jobs com a pesquisa escolhida (LSPA ou PIM-PF).

Manager · src/manager/main.py
2

Fatiamento

O Manager descobre o período corrente no SIDRA e quebra o pedido em uma tarefa por UF (27 tarefas).

dispatcher · build_tasks()
3

Publicação

As tarefas entram na fila do Redis em um pipeline (RPUSH). O Redis é só o broker.

Manager · redis.pipeline()
4

Consumo

Cada Worker espera a fila com BLPOP (bloqueante, sem polling) e pega uma tarefa por vez.

Worker · worker/main.py
5

Coleta (MAP)

O Worker consulta a API do SIDRA, converte os números do formato pt-BR e normaliza com pandas.

Worker · processor.py · sidra.py
6

Callback

O resultado volta por HTTP ao Manager, que grava os registros no SQLite e conta a tarefa como concluída.

Manager · /api/v1/internal/results
7

REDUCE

Quando a última tarefa fecha, o Manager consolida tudo e libera o relatório final na tela.

Manager · analysis.py · reduce_results()
8

Leitura

A interface busca GET /api/v1/results e desenha as tabelas com o relatório já pronto.

Painel · /painel/

4 · Três níveis de paralelismo

Nível 1 · entre os nós

Distribuído

— tarefas

O volume é quebrado por UF: cada tarefa é uma consulta independente ao SIDRA, executada por um Worker diferente.

Nível 2 · dentro do nó

Assíncrono (I/O)

— tarefas em voo

Cada Worker mantém até WORKER_CONCURRENCY requisições ao SIDRA simultâneas (asyncio.create_task), sem bloquear a fila.

Nível 3 · dentro da tarefa

Thread (CPU)

1 thread dedicada

A normalização em pandas é CPU-bound: roda em asyncio.to_thread para não travar o event loop do Worker.

6 · O que o REDUCE calcula

CategoriaVariáveis (agregado)HHIRanking (variável principal)
Sem job concluído ainda.

O ranking usa a variável principal da pesquisa (participação de cada UF no total); o HHI mede a concentração.

As fórmulas

Rodam no Manager, depois que todas as tarefas terminam.

soma = Σ valor(UF) média = Σ (valor(UF) × peso(UF)) / Σ peso(UF) part. % = 100 × valor(UF) / Σ valor(UF) HHI = Σ (part. % / 100)²
  • Soma — variáveis aditivas (produção, valor).
  • Média ponderada — variáveis de índice (preço, área média).
  • Participação — quanto cada UF responde pelo total.
  • HHI — concentração: <0,15 baixa · 0,15–0,25 moderada · >0,25 alta.

8 · Quando algo falha

Rede

Retry com backoff

Falha no envio ao Manager ou no acesso ao SIDRA? O Worker tenta de novo com espera exponencial (1 s, 2 s, 4 s) até MAX_RETRIES.

Tarefa

Reenfileiramento

Tarefa com erro volta para a fila do Redis com a tentativa incrementada; só é marcada como falha definitiva depois de esgotar as tentativas.

Nó morto

Heartbeat

Worker que para de responder some da lista em ~30 s (WORKER_STALE_SECONDS) — o Manager não depende de ninguém para continuar.

Escala

Mais nós, sem código

docker compose up -d --scale worker=5: a fila é compartilhada e os Workers novos entram na conta sozinhos.
